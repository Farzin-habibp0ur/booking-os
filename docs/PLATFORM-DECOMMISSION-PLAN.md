# Platform Decommission Plan — Feature Dispositions

> **Purpose:** A complete map of what BCC is shipping, what's deferred, and what's been removed in the AI Front Desk wedge pivot. Use this when you find a feature you don't recognize, when you're triaging a bug report against something we don't support anymore, or when you're answering "do you have X?" from a prospect.
>
> **Audience:** Engineering, founder, sales, support. Anyone who needs to know what's in scope for Year 1.
> **Last updated:** 2026-05-09

---

## How to read this document

Every major capability falls into one of four buckets:

- **KEPT** — shipped, supported, customer-facing, and part of the AI Front Desk SKU. Year-1 scope.
- **DEFERRED** — code present, may be partially functional, but explicitly off the customer surface during Year 1. Re-enabled when trigger conditions hit.
- **REMOVED** — deleted from schema, code, and UI. Not coming back in this form. (Some may return under different framing in Year 2.)
- **WHY** — the reason for the disposition, with links to the locked decisions in `BCC-PIVOT-MASTER-PLAN.md` (v3) where applicable.

If you're looking at code or UI that contradicts this document, file an issue. The doc is the source of truth for product scope; code drift gets cleaned up.

## Why each disposition (locked decisions)

### Why we kept the inbox + AI Front Desk surface

It's the wedge. Every product decision flows from "turn missed clinic messages into booked appointments." See `BCC-PIVOT-MASTER-PLAN.md` v3 Locked decisions reference > Brand and positioning.

### Why we deferred Capacitor

Owner-operators run their clinic from a phone, but a web inbox on a phone is good enough for Year 1. Native build adds CI/CD complexity and platform-specific bugs we don't have the bandwidth to chase during pilot. See `BCC-PIVOT-MASTER-PLAN.md` v3 Phase 6 task 4.

### Why we deferred the 12 in-app marketing agents

Path A (file-based primary) is the active growth engine. The in-app agents are the embryo of product #2 (AI Marketing Manager) — distinct product, distinct customer, distinct surface. Lighting them up during the AI Front Desk wedge would be a feature parade. See [`docs/AI-AGENT-ARCHITECTURE.md`](AI-AGENT-ARCHITECTURE.md). Path B trigger: 5+ paying clinics + a marketing hire.

### Why we removed clinical features

Compliance posture. Year-1 stance is non-HIPAA, non-PHI. Removing the schema (not just hiding the UI) makes the stance defensible — we are literally not handling PHI because the database doesn't accept it. See [`docs/COMPLIANCE-POSTURE.md`](COMPLIANCE-POSTURE.md). Year 2 may reintroduce some of these under HIPAA controls.

### Why we removed the GENERAL vertical pack

Year-1 ICP is medical spas only. Multi-vertical infrastructure was a pre-pivot artifact. Removing it forces the product to be opinionated for med spas, which is the wedge. See `BCC-PIVOT-MASTER-PLAN.md` v3 Phase 2 task 1.

### Why we kept `TreatmentPlan` and `TreatmentSession` (without photos)

Multi-session services (e.g., a 6-pack of microneedling) are a real med-spa workflow. They're service-package metadata, not medical detail. Keeping them lets us model service bundles cleanly without touching PHI. See `BCC-PIVOT-MASTER-PLAN.md` v3 Locked decisions reference > Compliance posture.

## How to handle "do you have X?" questions from prospects

If X is **KEPT** → "Yes, here's how it works." Show during the demo only if it's part of the wedge story; mention briefly otherwise.

If X is **DEFERRED** → "Not during pilot, but the code is there. We turn it on when [trigger condition]. Want me to add you to the watchlist?"

If X is **REMOVED** → "No, we removed that deliberately. Here's why: [link to COMPLIANCE-POSTURE.md or this doc]." Don't apologize for removed features. The removals are deliberate; explain confidently.

## How this doc stays accurate

Every PR that adds, removes, or defers a customer-facing feature must update this document. Add a row to the appropriate KEPT / DEFERRED / REMOVED table and reference the locked decision in `BCC-PIVOT-MASTER-PLAN.md` (or open a new ADR if the decision wasn't pre-locked).

Drift between this doc and reality is a bug. Treat it as one.
